## Dead Ends — Do Not Retry

### Proving escape elision as a throughput optimization

| Approach Tried                                                 | Why It Failed                                                                                                          | Time Spent                                      |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| Type-driven compile-time proof to skip runtime escape scanning | Measured at 16,780 ns with 4 elided vs 16,503 ns with none — runtime scan is already negligible (~few ns for `"8715"`) | ~2 hours including implementation + measurement |

**What to try instead**: Keep the pass for correctness (escaping numbers is a lie) and for native codec WASM boundaries, but do not claim it as a throughput lever.

### Making `data` form competitive

| Approach Tried                                   | Why It Failed                                                                                                                                                                                               | Time Spent                                                   |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Values-only projection through resident template | After brotli: 599 bytes vs 605 for `html` (1% difference). Client work: 1.07–1.33× MORE expensive than `html` in all three engines because values must parse and project before reaching native HTML parser | ~3 hours including implementation + cross-engine measurement |

**What to try instead**: Already resolved — cut the form entirely in IR 2.0.0. A `data` refresh is just a `delta` that declined to diff, so no regime where it wins.

### Zero-JavaScript out-of-order streaming

| Approach Tried                                                  | Why It Failed                                                                                                                                                                                                                             | Time Spent                              |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| Declarative shadow DOM slot assignment for out-of-order regions | Slot assignment only works on light-DOM children of a host **still open**. Keeping host open until content arrives IS in-order streaming. Out-of-order requires closed hosts, content arrives elsewhere, moving nodes requires JavaScript | ~4 hours including cross-engine testing |

**What to try instead**: Treat the 329-byte filler as the price of fastest-first, not a fallback. Zero-JS path is available for in-order streaming only.

## Key Decisions

- **Effect tracking is inference, not declaration**: Cache key, class, `Vary` headers all derived from read set. Trade-off: Hard bans on ambient reads (`process.env`, `Date.now()`) to keep inference complete.
- **IR 2.0.0 cuts `data` form**: A wire-breaking major. Rationale: Only 1% smaller after compression, slower to apply than `html`, and architecturally redundant (`delta` dominates for partials, `html` for full refreshes).
- **Two streaming orders, not a tuning knob**: `in-order` and `out-of-order` serve different constraints (zero-JS vs fastest-first). Trade-off: 329 bytes for 4.7× faster fast-region arrival.
- **Conventional commits enforced via hooks**: Commitlint + husky prevent non-conventional commits. Trade-off: Stricter process for automated changelog generation.
- **All dependencies pinned to exact versions**: No semver ranges. Rationale: Reproducible builds, explicit upgrade decisions via Renovate.

## Context for Future Sessions

**Design Claims vs Reality**

- Original design had 11 claims; 4 reversed by measurement, 2 not yet testable
- TTFB as phase-zero gate was conceptually wrong but premise survived — architectural advantage is in streaming, not first-byte latency
- `data` form cut creates wire break at IR 2.0.0 — older clients must refuse, not migrate

**Effect System Philosophy**

- Inference over declaration means read surface is closed — adding new context methods is a considered API change
- Hard bans are deliberate: one untracked `process.env` read invalidates entire cache guarantee
- Read keys must be string literals (no computed keys) because cache key derivation needs compile-time visibility

**Streaming Orders Trade-off**

- Not a tuning knob: architecturally different (declarative vs scripted filling)
- 329-byte filler is non-negotiable for out-of-order, not an optimization target
- Both orders produce identical DOM (verified across engines) — byte equality on wire is conformance gate

**Benchmark Harness as Design Enforcer**

- Aborts on wire form disagreement before any measurement
- Never aggregates engines — WebKit explicitly labeled as proxy, not iOS claim
- Noise floor enforcement prevents unfalsifiable claims
- Compiled fixtures in-process — numbers measured against emitted IR, not hand-optimized IR

**Dependency Management**

- Renovate configured for automated updates (`renovate.json`)
- All deps pinned exact (no `^` or `~`) for reproducibility
- TypeScript 7.0.2, Node 22.18+, pnpm 11.22.0

**Not Yet Built**

- No routing, request state machine, or plan system
- No two-phase envelope, 103 Early Hints, or ports
- No fragment composition (route contagion cannot fire without it)
- No actual kernel — current streaming is a test harness demonstrating the property
