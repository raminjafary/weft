## The byte decision, which came out differently than expected

The session opened on 359 bytes of headroom and a plan: take two free moves, re-measure, scope
the claim. All three happened, and then the accounting turned out to be wrong in a way that
mattered more than either.

**The two free moves paid 473 bytes.** `resolvePlugins` is build-time work — it infers plugin
ordering from static `reads`/`provides`, sorts, and refuses cycles, none of which involves a
request. `createKernel` now takes the resolved `PluginSchedule`. `guardReads` is the dev-time
check the design already describes as one, so it is passed in rather than imported.

**Then `createRouter` turned out never to have been in the measurement.** It was not exported
from `entry-request.ts`, so 7,602, 7,833 and 7,360 all described a kernel whose `serve()` throws
`E_NO_ROUTES`. Including it costs 639. **Net for the session on that figure: +166 bytes, and a
number that describes something deployable.**

**The claim is scoped and the scoping is a rule now.** The 8 KB covers the document request
path by name. Every other capability gets its own entry and its own stated ceiling rather than a
share of it. [`spec/kernel/budgets.md`](../spec/kernel/budgets.md) is normative. Six server
entries and four client entries are measured; where there is no design figure the ceiling is
called a watermark and two of them state how much room is left and what it is for.

**The rule was tested twice in the same session and held both times.** The channel came out 53
bytes over `entry-channel.ts`'s ceiling; the answer was a third entry, not a bigger second one,
and there is a real deployment behind the split. The stampede lease came out 13 bytes over
8,192; the answer was to move the policy behind a seam, which cost 59 bytes instead of 165 and
is better layering than the version that would have fitted.

## What was built

### The Warp transport binding — all three

`channel.ts` in the kernel is one state machine and knows none of the bindings: negotiation,
what each client holds per slot, staged epochs, watched keys, push invalidation. `node-channel.ts`
moves bytes three ways — a long-lived GET with discrete POSTs up, an SSE stream, and a
WebSocket. `node-websocket.ts` is RFC 6455 server-side, written rather than depended on, which
is what makes the test a real browser-grade client over a real socket.

What each binding costs is stated: SSE cannot carry binary, and the half-duplex bindings answer
on the other connection, so an upstream POST with no live downstream is `E_NO_DOWNSTREAM`.

Sixteen tests over real sockets, including the ten-connections-one-computation test and one
end-to-end test where a refresh over a socket becomes a single DOM write through the client's
own frame router.

### Intents

The only thing allowed to write. A write is declared and an undeclared one throws — not
dev-only, because an undeclared read is a missed optimisation and an undeclared write is a cache
invalidation nobody can predict from the code. The client never names server code: an opaque id,
resolved through the `registry` port, whose `manifestRegistry` derives ids with the same function
the compiler used.

A form posts and gets a 303 back where it came from. The same dispatch answers a `fetch` with
the outcome. Over a channel the epoch does the work: stage a guess, commit the truth, and on
failure discard — rollback needs no frame of its own.

An unchecked capability is refused, not allowed. `CapabilityCheck` is the seam phase 7 fills.

### The stampede lease, and a real worker pool

`StorePort.lease` existed and nothing took one. It is a `Coalescer` seam now, with
`leaseCoalescer` supplying the policy, because how a waiter waits is a property of the store —
an isolate-local map can only poll and a store with pub/sub should subscribe.

`workerPool` is real `worker_threads`, and it is what makes `.budget({ cpu })` a limit: a thread
can be terminated mid-loop where a cooperative signal cannot. Building it surfaced why the other
three off-thread executor kinds were unimplemented — `ExecutorPort.run` takes a closure, and a
closure cannot cross a crash domain. `RenderJob.address` is the fix, and a slot naming an
off-thread executor without one is a **lowering** error.

### Phase 6: incremental recompute, and the LiveView comparison

All three memoisation levels are real. Derived values whose inputs a change cannot reach are
carried over. Nested templates are content-addressed, so a 500-row list with three changed rows
costs three row renders and a _reordered_ list costs none. Byte identity with a full render is a
gate in `weft-bench verify`, cold memo and warm.

And the comparison phase 6 exists for, run: 1,000 clients on one base render cost **one** diff
against a per-connection differ's thousand, 0.3 ms against 8.2. **1,000 clients each on their
own base share nothing, and the shared path is then measurably worse — 17.3 ms against 9.2.**
Both are in the report.

## A bug-fixing pass at the end

Four defects, none of which broke a test. Each was a statement the code made that was not true.

- **`deferred` declared `kind: 'pool'`** and `preemptible: true`, so a reader had two reasons to
  believe it enforced a CPU budget against a synchronous loop. It only became a lie when a real
  pool existed to be confused with. `preemptible` is now `preemption: 'never' | 'at-await' |
'always'`, because a boolean could not tell the truth, and the breach message says which one
  happened.
- **A CPU budget on `deferred` warned about nothing.** `checkBudget` tested
  `spec.executor === 'inline'` — the literal string — when the condition is whether the target is
  a separate crash domain. `W_CPU_BUDGET_INLINE` is `W_CPU_BUDGET_ADVISORY` and names the
  executor. **A check written against one example of a condition tests the example.**
- **Base renders and memoized deltas never expired.** Fine on `memoryStore`, which is
  byte-bounded; unbounded growth on any shared store. Fifteen minutes by default, and an expired
  base costs a _form_ rather than correctness.
- **A channel buffered without limit for a peer that stopped reading.** Every sink ignored
  `res.write()`'s return. Sinks report `saturated` now and a channel saturated for 32 consecutive
  sends is closed with `E_SLOW_CONSUMER`. A channel is not a queue.

**And the line-count gate was re-derived a third time.** It fired on the backpressure fix, and
30% of what it was counting was documentation — a detector for absorbed work, firing because
somebody explained the work. It counts code lines now. `standards.test.ts` carries a commitment:
**a fourth re-derivation means deleting it rather than fixing it.**

The request path is **8,169 B against 8,192 — 23 bytes.** The next thing that wants to be in it
has a very short argument to make.

## Corrections Made Mid-Session — Read This First

### The server advertised an IR version it could not see

`SERVER_DEFAULTS.ir` in `@weft/warp` said `1.0.0`; the emitter has been on 2.4.0 since IR 2.0.0.
So every current client hit the IR-major branch and got `html` only — phase 6's whole mechanism
unreachable through the default negotiation. **A test was asserting that as correct behaviour**,
under the name "an IR major mismatch".

The fix is not a corrected constant: warp owns the Warp version and cannot see the IR's, so a
default there could only ever be wrong. `negotiate`'s second argument is required now,
`SERVER_DEFAULTS` is gone, and `serverCapabilities()` in the kernel composes both with a gate
asserting it equals `TEMPLATE_IR_VERSION`.

**A default in a module that cannot see the answer is a wrong answer waiting for a reader.**

### ACK was pointing the wrong way, and the gate for it passed

`ACK` was at `0x06` in the up range and used for the result of an intent, which travels down.
`codec.test.ts` already asserted every frame's declared direction agrees with its code range,
and that passed: the gate was checking the table against itself. What caught it was a real
socket. Warp **1.2.0** moves `ACK` to `0x22`; `0x06` is in a `RETIRED` list a test refuses to let
anything reuse.

### The test harness hid it for an afternoon

The down-stream reader ended in `.catch(() => {})`, so a reader that died on frame two looked
exactly like a server that never sent frame two. `settle()` reports the decode failure now.
**Two bugs in one afternoon were made harder to see by error handling written to keep a shutdown
path quiet.**

### An intent's invalidation reached nobody

An intent invalidates through its own declared-write guard, which calls `StorePort.invalidate`
directly, so the `StaleRegistry` was never consulted. Push invalidation worked for everything
except invalidations that came from a mutation — the only place they come from. `hub.notify` is
the path, and it excludes the connection that ran the intent, which is about to be handed the
new values. **Found by a test with two connections in it; one connection would have passed
forever.**

### The line-count ceiling should not have moved last session

It went 2,500 → 2,900 for routing, recorded then as something to be uncomfortable about. The
discomfort was right and the diagnosis was wrong: it was summing every file in `src/`, the same
gross-versus-marginal mistake the byte budget had already made and fixed. Measured against the
request path, routing never took it near 2,500. It is back at 2,500, per entry, by the same
reachability walk — plus a gate that every source file is reachable from some entry or named as
off it, because a module no ceiling applies to is invisible to both.

**Twice now a gate that fired and then moved turned out to have been measuring the wrong set.
Re-derive before renegotiating.**

### A queueing deadlock in the first worker pool

The dispatch loop handed one idle worker to every waiter it could see, because none of them had
had a turn to mark it busy. Two jobs on one worker, the second overwriting the first's pending
promise, and the first request waiting forever. Reserving is synchronous now where becoming busy
is not.

## Dead Ends — Do Not Retry

- **Do not put the stampede lease in the request path.** It is 13 bytes over 8,192, and the
  design's number does not move. `Coalescer` is the seam.
- **Do not give the kernel an opinion about how a waiter waits.** Polling is right for an
  isolate-local map and wrong for anything with pub/sub.
- **Do not memoise a text hole.** Hashing its value costs more than the escape scan and encode
  it replaces.
- **Do not try to share the segment memo across isolates.** `render` is synchronous by design;
  a shared tier cannot answer it, and making rendering async costs every render to benefit the
  ones that hit.
- **Do not expect a closure to reach a worker.** `ExecutorPort.run` takes one; anything off-thread
  needs `JobAddress`.
- **Do not reuse frame code `0x06`.** It is retired and a test enforces it.
- **`negotiate` has no default second argument any more.** Compose it with `serverCapabilities()`.
- **A plan slot on `pool:`/`isolate`/`binding:`/`svc:` needs `binding.address`.** One existing
  test had passed for a session while asserting a route the pool would have refused.

## Key Decisions

- **The 8 KB covers the document request path, and a new capability gets its own entry.** The
  alternative is one pool where the first feature spends the headroom and every later one argues.
- **A named ceiling with no design figure is called a watermark**, and two of them state how much
  room is left and what it is for, because a ceiling picked to fit what was just built is a label
  unless the next thing has to argue with it.
- **An undeclared write throws in production**, unlike an undeclared read. Different failure
  modes deserve different enforcement.
- **An unchecked capability is refused.** A decorative authority check is worse than none.
- **The shared-delta benchmark reports the case it loses.** Clients on different bases share
  nothing and the shared path is then slower; reporting only the aligned number would be advocacy.
- **`0x06` is retired rather than freed.** A reused code is the one version mistake a length
  prefix cannot protect a reader from.

## Pending Issues

Ordered by what blocks what. `ROADMAP.md` has the full version.

- [ ] **Instant navigation** — HIGH, and blocked somewhere unexpected. Bytes (103), templates
      (`WARM`/`TPL` + the resident store) and unpainted data (epochs) are all prepared for.
      What is missing is a route-scoped staging model and knowing a route's slot set before you
      arrive — which is **phase 7 discovery, not transport**. `NAV` (0x1d) is a declared code
      with no implementation.
- [ ] **A capability model behind `CapabilityCheck`** — HIGH. Intents refuse an unchecked
      capability, which is honest and is not an implementation. Signed intents are phase 7.
- [ ] **L0 static resolution** — MED. A fragment that reads nothing could be built once and
      served by a CDN with the kernel never invoked. Still the cheapest unimplemented thing.
- [ ] **Generated plans** — MED, and it is phase 8. `factsFrom` derives its input from compiler
      output; the plan and its bindings are hand-written.
- [ ] **Slots inside components / components in list rows** — MED.
      `E_COMPONENT_CHILDREN_UNSUPPORTED`, `E_COMPONENT_IN_LIST`.
- [ ] **The `patch` form** is in `derivableForms()` and no encoder produces it.
- [ ] **Phoenix has never run here.** The shared-delta comparison is architectural. Elixir on
      the machine would be a better test and the axis says so.
- [ ] **iOS WebKit on a real device** — LOW. Playwright WebKit is a desktop proxy, labelled as
      one everywhere.
